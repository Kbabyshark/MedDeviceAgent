# 医疗设备智能语音客服 Agent 平台
# 需求说明文档


## 1. 文档概述


## 1.1 项目背景

传统医疗设备客服系统主要依赖：

- 人工客服
- FAQ查询
- 固定规则机器人


存在：

- 知识检索效率低
- 无法理解复杂问题
- 无法结合用户设备信息
- 无法执行业务操作
- 高风险问题缺少安全控制


因此建设基于：

- LLM
- RAG
- Agent Workflow
- Tool Calling
- Human-in-the-loop

的医疗设备智能客服平台。


系统目标：

将传统知识问答升级为：
```

知识理解

- 

业务执行

- 

安全控制

- 

全过程追踪

```
的企业级智能客服 Agent。


---

# 2. 用户角色


系统主要包含以下角色：


## 2.1 普通用户


使用客服系统解决：

- 产品咨询
- 设备问题
- 故障排查
- 售后服务


能力：

- 文本咨询
- 语音咨询
- 查看处理结果
- 确认业务操作



---

## 2.2 客服人员


负责：

- 接管复杂问题
- 处理用户转人工请求
- 查看历史对话
- 查看Agent处理过程


能力：

- 查看会话
- 接管会话
- 查看工单
- 查看Trace



---

## 2.3 管理人员


负责：

- 知识库管理
- Prompt管理
- Agent配置
- 模型配置
- 权限管理



---

# 3. 核心业务需求


## 3.1 智能问答


系统需要支持用户：
```

用户问题

↓

理解意图

↓

检索知识

↓

生成回答

```
支持：

- 产品说明书查询
- FAQ查询
- 操作指导
- 功能介绍
- 参数说明


例如：

用户：

> 设备如何进行初始化？


系统：

根据设备型号检索说明书，并生成对应步骤。



---

# 4. 故障诊断需求


系统需要支持设备故障辅助分析。


支持：

- 故障码查询
- 故障原因解释
- 排查步骤推荐
- 处理建议


流程：
```

用户输入故障信息

↓

识别设备型号

↓

查询故障知识

↓

生成排查流程

```
注意：

系统只能提供设备故障排查建议。

禁止：

- 医疗诊断
- 治疗建议
- 用药建议



---

# 5. 售后业务需求


## 5.1 保修查询


支持：

用户查询：

- 当前设备是否保修
- 保修期限
- 服务范围


流程：
```

用户

↓

设备信息识别

↓

Warranty Tool

↓

返回结果

```
---

## 5.2 设备绑定查询


支持：

查询：

- 当前账号绑定设备
- 设备状态
- SN信息



要求：

必须校验用户身份。


---

## 5.3 创建维修工单


支持：

用户提交：

- 故障描述
- 设备信息
- 联系方式


系统生成：

工单草稿。


流程：
```

用户描述问题

↓

Agent生成工单

↓

用户确认

↓

创建工单

```
禁止：

未经用户确认直接创建。



---

## 5.4 转人工


支持：

用户主动：

- 请求人工
- 复杂问题升级


Agent生成：

- 转人工原因
- 问题摘要
- 历史上下文


减少人工重复询问。



---

# 6. Agent能力需求


## 6.1 意图识别


系统需要识别用户意图。


支持：
```
faq_query          # FAQ 查询
device_info_query  # 设备信息查询
fault_code_query   # 故障码查询
troubleshooting    # 故障排查
warranty_query     # 保修查询
device_binding     # 设备绑定查询
create_ticket      # 创建维修工单
transfer_human     # 转人工
medical_risk       # 医疗风险（安全拦截）
```
识别策略：
```

规则匹配

↓

LLM结构化分类

```
要求：

高频明确问题减少LLM调用。



---

# 6.2 Query Router


系统需要根据用户意图动态选择处理路径。


支持：

| 场景 | 路径 |
|-|-|
|设备知识问题|RAG|
|保修查询|Tool|
|设备查询|Tool|
|简单问题|直接回答|
|高风险问题|Safety流程|


避免：

所有请求同时执行RAG和Memory检索。



---

# 6.3 RAG知识库需求

向量数据库：Qdrant

LLM：DeepSeek（DeepSeek-V3 用于轻量任务，DeepSeek-R1 用于复杂推理任务）


系统需要支持企业知识检索。


知识来源：

- 产品说明书
- FAQ
- 故障码
- 售后政策
- 操作文档


支持：

- 文档解析
- Chunk切分
- Embedding
- 向量检索
- Metadata过滤


Metadata：

```json
{
 "device_type":"",
 "doc_type":"",
 "version":"",
 "permission":""
}
```

------

# 6.4 Tool Calling需求

系统需要支持Agent调用业务工具。

工具包括：

| Tool                   | 描述     |
| ---------------------- | -------- |
| query_warranty         | 查询保修 |
| query_device_binding   | 查询设备 |
| create_ticket          | 创建工单 |
| transfer_human         | 转人工   |

工具调用要求：

必须经过：

```
参数校验

↓

权限检查

↓

风险判断

↓

用户确认

↓

执行
```

------

# 6.5 Human-in-the-loop需求

高风险业务必须人工确认。

需要支持：

- 待确认状态
- 用户确认
- 用户取消
- 超时处理

State保存：

```
pending_action
```

------

# 7. Memory需求

系统需要支持多级上下文管理。

## 7.1 会话记忆

保存：

- 当前聊天上下文
- 当前任务状态

用于：

多轮对话。

------

## 7.2 摘要记忆

长对话自动摘要：

```
历史消息

↓

Summary

↓

减少Prompt长度
```

------

## 7.3 用户长期记忆

保存：

- 用户设备信息
- 历史服务记录

要求：

按照user_id隔离。

------

# 8. 语音能力需求

支持：

## ASR（FunASR + SenseVoice）

功能：

语音转文字。

特性：

- 端侧/服务端均可部署
- 支持中文医疗专业术语
- 流式识别

## TTS（CosyVoice 2）

功能：

文字转语音。

特性：

- 情感语音合成
- 支持多音色
- 流式合成

## WebSocket

支持：

- 实时语音通信
- 流式回复
- 状态推送

------

# 9. 安全需求

## 9.1 输入安全

检测：

- 医疗诊断请求
- 治疗建议
- 药物建议
- 隐私攻击

------

## 9.2 输出安全

检测：

- 虚假承诺
- 医疗风险回答
- 越权信息

风险问题：

进入：

```
safe_reply

或

人工客服
```
